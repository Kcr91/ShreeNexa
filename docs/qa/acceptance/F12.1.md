# F12.1 Acceptance Contract: Typed DhanBroker Order Mapping, Slicing, Static IP Validation, and Disabled-by-Default Feature Gate

## Feature Definition
- **Feature ID**: F12.1
- **Name**: Typed `DhanBroker` order mapping, idempotency keys, correlation IDs, order slicing (`/orders/slicing`), timeout/unknown-state handling, static IP validation (Lightsail primary or Local machine secondary), and disabled-by-default feature gate.
- **Dependencies**: F0.5, F0.6, F0.7, F9.1–F9.6, F13.1–F13.5
- **Proof Requirement**: Offline cassettes/state properties; unwhitelisted IP blocks order placement; no test can reach live Dhan; startup remains paper-only by default.

## Invariants & Acceptance Criteria

1. **Disabled-by-Default Feature Gate**:
   - `DhanBroker` defaults to `is_live_enabled = False`.
   - Any invocation of `place_order`, `modify_order`, `cancel_order`, or `place_sliced_order` while `is_live_enabled = False` raises `LiveTradingDisabledError`.
   - No test or default startup configuration can enable live trading without explicit environment opt-in (`SHREENEXA_ENABLE_LIVE_TRADING=true`).

2. **SEBI Static IP Preflight Verification**:
   - Before dispatching any order operation to Dhan, `DhanBroker` validates that the host outbound public IP matches either:
     - **Primary Static IP**: AWS Lightsail Mumbai production host.
     - **Secondary Static IP**: Authorized local workstation.
   - If the host IP does not match or cannot be verified against Dhan IP configuration (`/ip/getIP`), the order is rejected immediately with `StaticIPMismatchError` without calling order endpoints.

3. **Typed Order Request & Slicing Mapping (`backend/app/dhan/orders.py`)**:
   - Request and response models strictly adhere to DhanHQ v2.5 specifications:
     - `DhanOrderRequest`, `DhanOrderResponse`, `DhanOrderModifyRequest`, `DhanOrderCancelResponse`.
     - `DhanSliceOrderRequest`, `DhanSliceOrderResponse` (`/orders/slicing`).
   - Slicing logic automatically partitions orders exceeding exchange freeze limits (e.g., NIFTY freeze qty 1800) into sequential slices with unique correlation IDs.
   - Correlation IDs are deterministically linked to trade intents: `NEXA-<strategy_id>-<timestamp>-<uuid4_prefix>`.

4. **Timeout & Unknown-State Handling**:
   - Network timeouts or non-deterministic broker transport errors during order placement do **not** trigger blind retry (to prevent duplicate fills).
   - Orders with unknown transport state transition to `PENDING_BROKER_CONFIRMATION` requiring status polling via `get_order_by_correlation_id` before any subsequent action.

5. **Zero Secret Leakage & Offline Cassette Testability**:
   - Order exception representations and logs redact client secrets and access tokens.
   - All unit tests run 100% offline using `MockTransport` or `CassetteTransport`. No real network request is dispatched to Dhan live endpoints.

6. **Read-Only Status and Reconciliation Methods Exempt from Preflight Gate (QA-13)**:
   - Methods `get_order_by_id`, `get_order_by_correlation_id`, and `reconcile_pending_order` are read-only broker queries authorized across all execution modes (including default Paper mode).
   - They do not invoke `_verify_preflight_safety()`, ensuring post-timeout reconcilers and audit monitors can query broker truth without requiring live order placement enablement.
   - All mutating methods (`place_order`, `modify_order`, `cancel_order`, `place_sliced_order`) strictly enforce `_verify_preflight_safety()`.


## Required Deliverables
1. `backend/app/dhan/orders.py` — Typed order models, enums (`TransactionType`, `ProductType`, `OrderType`, `Validity`), and slicing request handlers.
2. `backend/app/engine/broker.py` — `DhanBroker` implementation adhering to the terminal execution contract with safety gates and IP validation.
3. `backend/tests/unit/test_dhan_orders.py` — Unit tests for order validation, serialization, and freeze-quantity slicing.
4. `backend/tests/unit/test_dhan_broker.py` — Unit tests for feature gate, static IP check, correlation IDs, and unknown state handling.
5. `backend/tests/cassettes/dhan/order_success.json`, `order_slice_success.json` — Offline response cassettes.
