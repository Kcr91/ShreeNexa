# F2.2 Acceptance Contract — Incremental Indicator Implementation and G1 Parity

## Feature

Stateful incremental / streaming technical indicator engine for all 12 registered indicator primitives with G1 vector-to-incremental mathematical parity enforcement.

## Scope decisions recorded before implementation

- **Standardized Incremental Interface**:
  - `IncrementalIndicator` abstract base class defining:
    - `name: str`
    - `update(bar: BarRecord | dict[str, float]) -> float | dict[str, float] | None`
    - `reset() -> None`
    - `is_ready: bool`
    - `state: dict[str, Any]` (checkpoint serializable)
- **Incremental Implementations for All 12 Primitives**:
  - **Trend**:
    - `IncrementalSMA`: Rolling queue with $O(1)$ sum update.
    - `IncrementalEMA`: Exponential alpha recurrence seeded with initial $N$-bar SMA.
    - `IncrementalMACD`: Fast/Slow/Signal EMA state machines.
    - `IncrementalSupertrend`: Wilder TR accumulation and trailing band flip logic.
  - **Momentum**:
    - `IncrementalRSI`: Gain/loss Wilder smoothing.
    - `IncrementalStochastic`: Rolling min/max window for $\%K$ and $\%D$ SMA smoothing.
    - `IncrementalROC`: $N$-bar rolling lookback queue.
  - **Volatility**:
    - `IncrementalATR`: True range Wilder smoothing.
    - `IncrementalBollingerBands`: Rolling Welford / moving sum and sum-of-squares variance.
  - **Volume**:
    - `IncrementalOBV`: Cumulative signed volume accumulator.
    - `IncrementalVWAP`: Cumulative price-volume and volume accumulators.
  - **Statistical**:
    - `IncrementalZScore`: Rolling mean and standard deviation.
    - `IncrementalRollingStd`: Rolling variance / standard deviation.
- **Dual Implementation Invariant (G1)**:
  - No indicator primitive may be registered without both a Vector and Incremental implementation.
- **Parity Property Tests**:
  - Property-based and fixture test suites validating that $N$ sequential `update()` calls yield identical outputs to `VectorIndicator.compute()` on the same input series within $10^{-4}$ tolerance.

## Required deliverables

1. `backend/app/indicators/incremental.py` — `IncrementalIndicator` base class, factory, and state management.
2. `backend/app/indicators/incremental_primitives.py` — Incremental implementations for all 12 primitives.
3. `backend/app/indicators/__init__.py` — Package exports.
4. `docs/qa/acceptance/F2.2.md` — Acceptance contract.
5. `backend/tests/unit/test_incremental_indicators.py` — G1 vector/incremental parity tests across all primitives.

## Acceptance scenarios

### B1 — Complete incremental parity coverage
- Every vector primitive in the registry has a matching incremental implementation.

### B2 — G1 mathematical parity verification
- Streaming bar-by-bar updates yield exact numeric parity ($\le 10^{-4}$ error) compared to batch vector computation across all 12 indicators.

### B3 — Warm-up period and readiness flag
- Returns `None` and `is_ready = False` during warm-up bars, transitioning to valid numeric returns upon warm-up completion.

### B4 — Reset and state idempotency
- Invoking `reset()` clears historical buffers and resets state cleanly.
