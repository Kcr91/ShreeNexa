# F4.2 Acceptance Contract — Typed Widget Registry with Settings Validation and Lazy Loading

## Feature

Extensible typed widget registry for ShreeNexa Terminal with JSON/TypeScript settings schema validation, lazy component loading (`React.lazy` + `Suspense`), categorized widget palette, and dynamic discovery without modifying layout code.

## Scope decisions recorded before implementation

- **Typed Widget Definition Contract**:
  - Every widget exports metadata (ID, title, description, category, default dimensions, icon), a settings schema with field validators, and a React component.
- **Dynamic Registry & Palette Discovery**:
  - Registering a new `WidgetDefinition` makes it immediately discoverable in the widget palette without modifying any dashboard or layout code.
- **Settings Schema Validation**:
  - Strict validation of widget parameters (required fields, numeric min/max bounds, enum options) before applying settings.
  - Invalid settings fail visibly with clear error messages without crashing the widget frame.
- **Lazy Loading & Suspense**:
  - Widgets load asynchronously via `React.lazy` with fallback `LoadingSkeleton` to maintain responsive initial bundle size.

## Required deliverables

1. `frontend/src/widgets/types.ts` — Type definitions for schemas, settings, definitions, and component props.
2. `frontend/src/widgets/registry.ts` — `WidgetRegistry` singleton with registration, query, and validation methods.
3. `frontend/src/widgets/builtin/` — Initial built-in widgets (`MarketClockWidget.tsx`, `BacktestSummaryWidget.tsx`, `WatchlistWidget.tsx`, `FixtureTestWidget.tsx`).
4. `frontend/src/widgets/WidgetFrame.tsx` — Widget container frame with header, action buttons, suspense loading, and error states.
5. `frontend/src/widgets/WidgetPalette.tsx` — Categorized widget picker component.
6. `frontend/src/widgets/registry.test.ts` & `frontend/src/widgets/WidgetFrame.test.tsx` — Unit tests.
7. `docs/qa/acceptance/F4.2.md` — Acceptance contract.

## Acceptance scenarios

### B1 — Dynamic registration and palette visibility
- A fixture widget registered at runtime immediately appears in `getAllWidgets()` and the widget palette without modifying any layout code.

### B2 — Settings schema validation and error reporting
- Submitting out-of-range numeric settings or invalid selection options fails schema validation and returns explicit validation errors.

### B3 — Lazy loading and suspense fallback
- Widget components render asynchronously with Suspense fallback and mount cleanly upon load.
