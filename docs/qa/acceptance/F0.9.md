# F0.9 Acceptance Contract — Connection Budget Manager

## Feature

Central connection-budget manager for Dhan market-feed and depth WebSocket sockets, with a conservative default shared pool of 5 (split 3 feed / 2 depth) and configuration switch for independent pools (5 feed / 5 depth), explicit exhaustion errors, and property-tested connection ceilings.

## Scope decisions recorded before implementation

- **Single Owner Boundary**:
  - `feedd` process owns every Dhan socket connection (ADR-0002).
  - No other process or component opens raw Dhan WebSockets directly.
- **Shared vs Independent Pool Allocation**:
  - **Default (Shared)**: Hard ceiling of 5 total concurrent connections across all types. Default split: max 3 feed sockets, max 2 depth sockets, sum <= 5.
  - **Independent**: Configured with `pool_mode: independent` allowing up to 5 feed sockets AND up to 5 depth sockets (10 total).
- **Ceiling Invariant & No Silent Drops**:
  - Dhan's broker API silently disconnects the oldest connection if a 6th socket is opened on a shared user pool.
  - The budget manager strictly blocks and rejects any request exceeding the budget with `ConnectionBudgetExhaustedError`.
  - Never silently drops or disconnects active leases without explicit release.
- **Lease Lifecycle & Idempotency**:
  - `acquire()` yields a typed `ConnectionLease` with unique `lease_id`, `socket_type`, and timestamp.
  - Supports both async context manager (`async with manager.lease(SocketType.FEED) as lease:`) and explicit `release(lease)`.
  - Releasing an already-released lease is safe and idempotent (no double-decrement).
- **Concurrency & Robustness**:
  - Thread-safe and asyncio-safe synchronization.
  - Hypothesis property tests prove that arbitrary sequences of concurrent acquires, releases, and timeouts never violate the ceiling.

## Acceptance scenarios

### B1 — Configuration loading
- Loads `config/feed_budget.yaml` defaulting to `shared` mode with total capacity 5 (3 feed / 2 depth).
- Validates that shared pool split does not exceed total capacity.

### B2 — Shared pool ceiling enforcement
- In shared mode (capacity 5), acquiring 3 feed and 2 depth succeeds.
- Attempting to acquire a 6th connection raises `ConnectionBudgetExhaustedError`.
- No sequence of operations allows active connections to exceed 5.

### B3 — Independent pool mode
- When configured with `pool_mode="independent"`, up to 5 feed and 5 depth connections can be acquired concurrently.
- Attempting to acquire a 6th feed or 6th depth connection raises `ConnectionBudgetExhaustedError`.

### B4 — Idempotent release and cleanup
- Releasing a lease frees the capacity immediately.
- Releasing the same lease multiple times does not corrupt capacity counts.

### B5 — Timeout on acquire
- When pool is full, acquiring with a timeout waits up to the timeout; if no lease is released, raises `ConnectionBudgetExhaustedError`.
- If a lease is released while waiting, the waiting acquire completes successfully.

### B6 — Hypothesis property testing
- Randomized concurrent interleaving of acquires, releases, and timeouts maintains active connection counts <= total capacity invariant at every step.
