# M0.6 Acceptance Contract — First Green Baseline and Hashed Reference Fixtures

## Feature

Prove that a completely fresh clone of the repository bootstraps and passes every currently defined gate with no manual setup beyond what `AGENTS.md` documents, and freeze a small set of synthetic/reference fixtures by cryptographic hash for later numeric-parity features (F1.6 resampling, F2.1 indicator registry, and similar) to pin against.

## Required deliverables

1. `.gitattributes` forcing LF line endings for the new fixture files, so their recorded hashes are stable across Windows/Linux clones regardless of local `core.autocrlf`.
2. `build/fixtures/ohlc_synthetic_10bar.csv` — a small, hand-authored 10-bar daily OHLCV series for a fictitious instrument, with values chosen so downstream indicator math is hand-verifiable.
3. `build/fixtures/sma_ema_reference.json` — hand-computed SMA(3) and EMA(3) reference values for the closes in the CSV above, computed independently of any indicator library, with an explicit warm-up/`null` policy for the first two bars.
4. `build/fixtures/manifest.json` — records the SHA-256 of every fixture file.
5. `build/validate_fixtures.py` — recomputes each fixture's SHA-256 and compares it to the recorded value; fails on a hash mismatch, an unrecorded fixture file, or a recorded file that no longer exists.
6. `build/tests/test_fixtures.py` — pytest coverage: hashes match on the real fixtures; a single-byte tamper is detected; an untracked extra fixture file is detected; a missing fixture file is detected; the hand-computed SMA/EMA values are independently re-derived from the CSV and shown to match the recorded reference.
7. Evidence that a real fresh clone (not just the existing working tree) passes `build/validate_manifest.py`, `build/validate_fixtures.py`, and `pytest build/tests` with no steps beyond `git clone` and the Python version already documented in `AGENTS.md`.
8. Project-status update in `PROJECT_UPDATE.md` after implementation and after independent review.

## Acceptance scenarios

### A1 — Clean-clone bootstrap is green

- A fresh `git clone` of the local repository, in an isolated directory, with no `pip install` beyond what's already globally available (PyYAML, pytest, ruff — the same environment `AGENTS.md` currently assumes pre-F0.1) runs:
  - `python build/validate_manifest.py` — exits 0.
  - `python build/validate_fixtures.py` — exits 0.
  - `python -m pytest build/tests -q` — all pass.
- No unexplained warning appears in that output (line-ending warnings from `git add`/`git diff` on the clone are expected and are not "unexplained" — they are explicitly checked and shown not to affect the recorded hashes).

### A2 — Fixtures are frozen by hash, not by trust

- `build/manifest.json` names every file under `build/fixtures/` exactly once, each with a SHA-256 digest.
- `build/validate_fixtures.py`, run against the real fixtures, reports zero mismatches.
- A test that flips one byte in a copy of a fixture and re-validates proves the check is real, not vacuous.
- A test with an extra file under `build/fixtures/` not present in `manifest.json` fails validation (silent fixture drift is not possible).

### A3 — Reference values are independently hand-derived

- SMA(3)/EMA(3) values in `sma_ema_reference.json` are computed by hand (or by a from-scratch loop, not an indicator library) and documented well enough that a reviewer can redo the arithmetic from the CSV alone.
- The warm-up policy (first `window - 1` bars are `null`, not zero or a partial average) is explicit and tested.

- `python build/validate_fixtures.py` — exits 0 against the real fixtures.
- `python -m pytest build/tests -q` — all pass, including the new fixture tests.
- `python -m ruff check build/` — clean.
- Perform an actual `git clone` of the local repository into a temporary directory, run the three commands above there, and record the exact output before deleting the temporary clone.
- Resolve local Markdown links, scan changed files for secret-shaped content, and run `git diff --check`.

## Non-goals

- No backend/frontend scaffolding, dependency lockfiles, or CI wiring — that is F0.1.
- No indicator registry implementation — the SMA/EMA reference values exist only as frozen fixtures for a *future* feature (F2.1) to validate against; M0.6 does not implement or register an indicator.
- No repo-wide line-ending renormalization of already-tracked files — `.gitattributes` is scoped to the new fixture files only, to avoid an unrelated mass-reformat commit.

## Migration and rollback

New files only; no schema or runtime-data impact. Revert the M0.6 commit(s) to roll back before F0.1 depends on a green baseline existing.
