# F2.5 Acceptance Contract — Incremental Compound Indicator Engine

## Feature

Streaming real-time compound indicator engine executing topological calculation DAGs on a bar-by-bar basis with exact G1 parity against batch vectorized graph execution.

## Scope decisions recorded before implementation

- **Incremental Graph Pipeline**:
  - `IncrementalGraphEngine` built from an `IndicatorDependencyGraph` or topological plan.
  - Instantiates stateful `IncrementalIndicator` instances for primitives and evaluates formula logic incrementally for each new incoming bar.
- **Bar Update Protocol**:
  - `update(bar: BarRecord | dict[str, Any]) -> dict[str, float | bool | None]`:
    - Evaluates nodes in topological dependency sequence.
    - Upstream intermediate results computed for the current bar are immediately available to downstream formula nodes.
- **State Checkpointing & Recovery**:
  - `state` property serializing states of all nested indicators across the graph.
  - `restore_state(checkpoint)` restoring complete multi-node state idempotently.
  - `reset()` clearing all internal buffers.
- **Simulation Parity Verification**:
  - Validates that streaming $N$ bars sequentially through `IncrementalGraphEngine.update()` reproduces the exact outputs of `IndicatorExecutionPlan.execute()` on the same bar series within $10^{-3}$ tolerance.

## Acceptance scenarios

### B1 — Real-time bar-by-bar compound graph processing
- Updates a multi-node compound DAG sequentially in $O(1)$ per bar.

### B2 — G1 vector/incremental compound graph parity
- Output streams match batch vector execution across single and multi-stage dependent nodes.

### B3 — State checkpointing and restoration
- Freezes and restores compound graph state across streaming iterations.

### B4 — Reset lifecycle
- Cleanses internal buffers on reset.
