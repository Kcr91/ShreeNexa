# F0.5 Acceptance Contract — Typed Dhan REST Wrapper with Injectable Transport and Recorded Cassettes

## Feature

Implement a robust, fully typed DhanHQ v2 REST API client (`backend/app/dhan/client.py`) with an injectable transport layer (`backend/app/dhan/transport.py`), explicit error classifications (`backend/app/dhan/exceptions.py`), typed response and request models (`backend/app/dhan/models.py`), and comprehensive offline testing against recorded, sanitized JSON cassettes (`backend/tests/cassettes/dhan/*.json`).

## Scope decisions recorded before implementation

- **Injectable Transport Architecture**: The Dhan client does not hardcode network libraries; it delegates HTTP interactions to an injectable `DhanTransport` implementation.
  - `HTTPTransport`: Standard network transport using Python standard library `urllib.request` / `http.client` with timeouts, headers, and secret redaction.
  - `CassetteTransport`: Deterministic offline transport replaying recorded sanitized JSON response cassettes matching method and endpoint paths.
  - `MockTransport`: Programmatic mock transport for simulating network failures, connection resets, and dynamic status codes.
- **Typed Error Hierarchy & Retryability**:
  - `DhanError`: Base class for all Dhan client errors.
  - `DhanAuthenticationError`: 401 Unauthorized, invalid token, or expired token. `is_retryable = False`.
  - `DhanRateLimitError`: 429 Too Many Requests. `is_retryable = True`.
  - `DhanServerError`: 500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable, 504 Gateway Timeout. `is_retryable = True`.
  - `DhanTimeoutError`: Connection timeout or read timeout. `is_retryable = True`.
  - `DhanClientError`: 400 Bad Request, 404 Not Found, 422 Unprocessable Entity. `is_retryable = False`.
  - `DhanMalformedResponseError`: Unparseable JSON or missing mandatory response fields. `is_retryable = False`.
- **Zero Secret Exposure**:
  - The client and transport MUST NEVER log, stringify, or include raw `access-token` values in exceptions, logs, or traces. All headers and error representations are filtered through secret redaction.
- **Offline Recorded Cassettes**:
  - Authentic, sanitized cassettes under `backend/tests/cassettes/dhan/*.json` simulate realistic Dhan responses:
    - `profile_success.json`: Account fund limit and profile metadata.
    - `historical_daily_success.json`: Daily OHLCV historical bars.
    - `historical_intraday_success.json`: 1-minute OHLCV intraday bars.
    - `auth_failure_401.json`: 401 Unauthorized / Token Expired error payload.
    - `rate_limit_429.json`: 429 Rate Limit Exceeded error payload.
    - `server_error_503.json`: 503 Service Unavailable error payload.
    - `malformed_response.json`: Invalid JSON / schema-breaking payload.
- **Typed Endpoints Supported**:
  - `get_fund_limits()` -> `DhanFundLimit`
  - `get_profile()` -> `DhanProfile`
  - `get_historical_daily(security_id, exchange_segment, instrument_type, from_date, to_date)` -> `DhanHistoricalData`
  - `get_historical_intraday(security_id, exchange_segment, instrument_type, from_date, to_date, interval)` -> `DhanHistoricalData`
  - `get_quote(security_id, exchange_segment)` -> `DhanQuote`
  - `get_holdings()` -> `list[DhanHolding]`
  - `get_positions()` -> `list[DhanPosition]`

## Required deliverables

1. `backend/app/dhan/exceptions.py` — Error hierarchy with `is_retryable` attribute, status codes, and secret redaction in error messages.
2. `backend/app/dhan/models.py` — Typed Pydantic models for Dhan responses and request payloads.
3. `backend/app/dhan/transport.py` — `DhanTransport` protocol, `HTTPTransport`, `CassetteTransport`, and `MockTransport`.
4. `backend/app/dhan/client.py` — `DhanRestClient` implementation with typed convenience methods and error mapping.

8. `backend/tests/unit/test_dhan_cassettes.py` — Offline cassette-driven tests covering success, auth failure, malformed response, timeout, and retryable error.

## Acceptance scenarios

### A1 — Successful requests with cassette replay
- `client.get_fund_limits()` parses `profile_success.json` into typed `DhanFundLimit`.
- `client.get_historical_daily(...)` parses `historical_daily_success.json` into typed `DhanHistoricalData` with matching bar counts and timestamps.
- `client.get_historical_intraday(...)` parses `historical_intraday_success.json` into typed `DhanHistoricalData`.

### A2 — Authentication failure handling
- Receiving 401 or token expired error raises `DhanAuthenticationError`.
- `error.is_retryable` is `False`.
- The exception message and representation redact all tokens and client secrets.

### A3 — Malformed and schema-breaking responses
- Receiving non-JSON text or missing expected data keys raises `DhanMalformedResponseError`.
- `error.is_retryable` is `False`.

### A4 — Timeout and connection errors
- Network connection timeout or read timeout raises `DhanTimeoutError`.
- `error.is_retryable` is `True`.

### A5 — Retryable server and rate limit errors
- Receiving 429 raises `DhanRateLimitError` with `is_retryable = True`.
- Receiving 500/502/503/504 raises `DhanServerError` with `is_retryable = True`.
- Receiving 400/422 raises `DhanClientError` with `is_retryable = False`.

### A6 — Zero secret leakage
- Calling any method with invalid or valid credentials never logs or leaks `access-token` in exception `str()` or `repr()`.

## Non-goals

- No real network calls to Dhan during automated test runs.
- No live broker order execution or modification (Epic 12).
- No token generation or renewal automation.
- No protected-path edits (`backend/app/engine/risk.py`, `backend/app/engine/broker.py`, `backend/app/dhan/orders.py`, `backend/tests/parity/`).
