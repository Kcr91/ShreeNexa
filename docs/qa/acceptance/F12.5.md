# F12.5 Acceptance Contract: Continuous Positions/Orders/Funds Reconciliation Against Dhan with Freeze-on-Mismatch Policy

## Feature Definition
- **Feature ID**: F12.5
- **Name**: Continuous positions/orders/funds reconciliation against Dhan with freeze-on-mismatch policy.
- **Dependencies**: F12.1, F12.2, F12.3, F12.4
- **Proof Requirement**: Seeded mismatch freezes affected trading and creates a clear resolution workflow; no silent auto-correction.

## Invariants & Acceptance Criteria

1. **Continuous Reconciliation Invariant (`backend/app/engine/continuous_recon.py`)**:
   - The reconciliation engine compares authoritative Dhan broker snapshots (positions via `get_positions()`, orders via `get_order_list()`, funds via `get_fund_limits()`) against local engine state.
   - Any deviation in position net quantity, order status, or cumulative fill count triggers an immediate mismatch state.

2. **Freeze-on-Mismatch Policy (Zero Silent Auto-Correction)**:
   - When a mismatch is discovered, the affected symbol or account is **immediately frozen** (`is_frozen = True`).
   - The system **never** silently overrides local numbers or adjusts positions behind the scenes without explicit operator command.
   - Any order routing attempt for a frozen symbol is rejected with `RiskCheckFailedError("Trading is frozen for {symbol} due to active reconciliation mismatch")`.

3. **Structured Incident & Operator Resolution Workflow**:
   - Every mismatch creates a durable `MismatchIncident` recording:
     - `incident_id`: unique identifier.
     - `dimension`: `"POSITION"` | `"ORDER"` | `"FUNDS"`.
     - `symbol` / `security_id`.
     - `local_value` vs `broker_value`.
     - `detected_at`: UTC timestamp.
     - `status`: `"ACTIVE_FROZEN"` | `"RESOLVED"`.
   - Resolution requires explicit operator invocation: `resolve_mismatch(incident_id, resolution="OVERRIDE_TO_BROKER" | "MANUAL_ADJUSTMENT", operator_notes="...")`.
   - Unfreezing occurs only after the incident is formally marked resolved.

4. **Zero Real Broker Order Placement in Tests**:
   - Test suites use mock transports and seeded discrepancy states. Zero live broker order placement occurs.

## Required Deliverables
1. `backend/app/engine/continuous_recon.py` — Continuous reconciliation coordinator, incident management, and freeze policy.
2. `backend/app/engine/risk.py` — Integrate freeze check into `RiskEngine.filter_order()`.
3. `backend/tests/unit/test_continuous_recon.py` — Proof test suite demonstrating seeded mismatch freezes trading, generates incident, prevents silent auto-correction, and requires operator resolution.
