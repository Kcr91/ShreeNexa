# F3.1 Acceptance Contract — Engine Contracts for Clock, DataSource, Broker, Portfolio, Events, and Persistence

## Feature

Core execution engine contracts and state machine models establishing the unified execution abstractions across backtesting (`SimClock`, `HistoricalDataSource`, `SimBroker`), paper trading, and live execution, with checkpointing and state recovery guarantees.

## Scope decisions recorded before implementation

- **Clock Abstraction**:
  - `Clock` base protocol.
  - `SimClock`: Discrete step advance over sorted bar timestamps for backtesting.
  - `RealClock`: Real-time system clock for live and paper sessions.
- **DataSource Abstraction**:
  - `DataSource` protocol.
  - `HistoricalDataSource`: Emits bars chronological tick-by-tick / bar-by-bar without forward lookahead.
  - `LiveDataSource`: Emits streaming bars from live feed.
- **Broker Interface**:
  - `Broker` protocol with `submit(orders)`, `cancel(order_id)`, `get_positions()`, and `get_account_balance()`.
- **Order & Fill Contracts**:
  - `OrderRequest`: Strongly-typed order request model (`order_id`, `security_id`, `exchange_segment`, `side`, `quantity`, `order_type`, `price`, `trigger_price`, `time_in_force`, `tag`, `created_at`).
  - `OrderResult`: Broker submission acknowledgment (`order_id`, `status`, `reason`, `submitted_at`).
  - `FillEvent`: Execution fill model (`fill_id`, `order_id`, `security_id`, `exchange_segment`, `side`, `quantity`, `price`, `timestamp`, `brokerage`, `taxes`, `slippage`).
- **Portfolio & Position State Machine**:
  - `Position`: Tracks active quantity, average price, realized PnL, and unrealized PnL.
  - `Portfolio`: Tracks cash, margin, positions, fill ledger, and equity curve.
  - Correctly handles position flip (e.g. from Long to Short in a single fill), partial closes, and mark-to-market valuations.
- **Event Bus & Event Lifecycle**:
  - Typed engine events: `BarEvent`, `SignalEvent`, `OrderEvent`, `FillEvent`, `PositionUpdateEvent`.
- **Checkpointing & State Recovery (State Machine Property)**:
  - `get_state()` / `restore_state()`: Serializes and restores complete engine state.
  - Invariant: Advancing from restored checkpoint $C_t$ by $N$ steps produces identical portfolio equity and positions to an uninterrupted $0 \dots t+N$ run.

4. `backend/tests/unit/test_engine_contracts.py` — Unit tests covering clock stepping, portfolio state machine transitions, position flips, and checkpoint restore equivalence.

## Acceptance scenarios

### B1 — SimClock and HistoricalDataSource stepping
- Steps through chronological bar timestamps and advances data source without future lookahead.

### B2 — Portfolio state machine and position flip
- Applies buy, sell, partial exit, and full position reversal (Long -> Short) fills, correctly updating cash balance, average entry price, realized PnL, and mark-to-market equity.

### B3 — Checkpoint state recovery equivalence
- Runs engine to bar $t$, takes checkpoint $C_t$, and verifies that restoring into a new engine and running to $t+N$ yields identical portfolio equity, cash, and positions as the continuous run.
