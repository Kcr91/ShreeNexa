# F5.3 Acceptance Contract: Visual Strategy Builder AI Draft Rendering, Diff, and Approval Gate

## Feature Definition
- **Feature ID**: F5.3
- **Name**: Render generated IR in the visual builder with diff, explanation, warnings, edit, approve, reject, and draft-only status.
- **Dependencies**: F2.4, F5.2
- **Proof Requirement**: Playwright confirms generation never changes deployment state and requires user approval before save.

## Invariants & Acceptance Criteria

1. **AI Strategy Assistant Integration**:
   - Integrated into the Visual Strategy Builder (`StrategyBuilderWidget.tsx`) via an explicit "AI Strategy Assistant" action.
   - Allows users to enter natural language strategy prompts or pick curated templates (e.g. "EMA Crossover", "RSI Mean Reversion", "Bollinger Breakout").
   - Communicates with `/api/v1/ai/generate-strategy` to synthesize schema-valid `StrategyIR`.

2. **Draft-Only Status & Zero Deployment Impact Invariant**:
   - All AI-generated strategy representations default to `status: "DRAFT"`.
   - Deployment state is strictly locked to `deployment_state: "DISABLED"` / `"UNTOUCHED"`.
   - The UI surfaces prominent badges confirming:
     - "Status: DRAFT ONLY"
     - "Deployment: UNTOUCHED / DISABLED"
   - Under no circumstances does AI generation auto-deploy, save to production, or modify active live/paper allocations without explicit manual user approval.

3. **Diff View (Current vs Draft)**:
   - Provides a side-by-side or structured comparison between the current visual builder strategy and the proposed AI draft:
     - Strategy Name
     - Target Universe & Timeframe
     - Added or altered indicator pipelines
     - Rule definitions (Entry / Exit signals and thresholds)
     - Risk parameters (Stop Loss %, Take Profit %)

4. **Explanation and Warnings Panels**:
   - Renders the structured natural language explanation describing the generated strategy's mechanics, regime suitability, and indicator roles.
   - Renders any validation warnings or risk advisories (e.g. tight stop loss, lack of exit condition, high timeframe mismatch).

5. **User Decision & Action Workflow**:
   - **Edit**: User can edit draft parameters directly before taking action.
   - **Approve**: User explicitly approves the draft. The draft is applied to the visual builder workspace, ready for local vector backtesting.
   - **Reject**: User discards the draft. The visual builder workspace remains completely unchanged.

6. **Quality & Boundary Compliance**:
   - Zero edits to protected paths (`backend/app/engine/risk.py`, `backend/app/engine/broker.py`, `backend/app/dhan/orders.py`, `backend/tests/parity/`).
   - TypeScript strict typecheck passing.
   - Vitest component tests passing.
   - Full repository checks clean.
