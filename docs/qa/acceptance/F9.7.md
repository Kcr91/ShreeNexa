# F9.7 Acceptance Contract — Paper P&L Calendar and Monthly/Yearly Returns by Reusing F3.12–F3.14

## Feature

Paper trading accounts surface monthly/yearly P&L calendar grids, daily records, and continuous return timelines by directly reusing the Epic 3 quantitative accounting ledger (`DailyPnLTracker`), ensuring zero duplicated calculation paths and bit-for-bit reconciliation between execution modes.

## Scope decisions recorded before implementation

- **Direct Ledger Reuse (Zero Calculation Forks)**:
  - Daily P&L and Time-Weighted Return (TWR) tracking for paper trading directly instantiates `app.engine.daily_pnl.DailyPnLTracker` with `mode=ExecutionMode.PAPER`.
  - Zero duplicate formulae for gross P&L, MTM change, transaction cost deduction, daily return rate, or geometric TWR linking.
- **Data Reconciliation (`source_kind='paper'`)**:
  - `PaperCalendarAdapter` builds daily accounting snapshots from `PaperRepository` trade fills, realized position P&L, and equity curve snapshots.
  - Reconciles starting equity, cashflows, realized P&L, MTM, costs, and ending equity identically to the accounting identity:
    `E_end = E_start + Cashflow + P_real + delta_MTM - Costs`.
  - Aggregates cleanly into monthly and yearly summaries with green/red day counts, win rates, and compounded returns.
- **REST API Endpoints**:
  - `GET /api/v1/paper/calendar`: Query monthly/yearly calendar summaries and daily records for a paper account.
  - `GET /api/v1/paper/returns`: Query time-series return points structured as `TimelinePhaseSlice` with `phase="PAPER"` ready for continuous timeline stitching.
- **Frontend Integration**:
  - `PnlCalendarWidget` supports switching between `sourceKind="backtest"` and `sourceKind="paper"`.
  - `ReturnsTimelineWidget` seamlessly stitches `PAPER` phase slices into the unified cross-phase returns timeline.

## Required deliverables

1. `backend/app/paper/calendar.py` — Adapter transforming paper repository data into `DailyPnLTracker` records and calendar summaries.
2. `backend/app/api/paper.py` — REST endpoints for paper calendar and returns.
3. `backend/app/paper/__init__.py` — Package exports for paper calendar functions.
4. `frontend/src/pnlcalendar/types.ts` & `frontend/src/widgets/builtin/PnlCalendarWidget.tsx` — Add `sourceKind` to settings and display paper calendar data.
5. `backend/tests/unit/test_paper_pnl_calendar.py` — Unit tests proving reconciliation, zero duplication, and REST API contract.
6. `docs/qa/acceptance/F9.7.md` — Acceptance contract.
