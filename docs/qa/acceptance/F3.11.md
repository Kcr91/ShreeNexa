# F3.11 Acceptance Contract — Grading Thresholds UI and Scorecard Management

## Feature

Configurable metric grading thresholds manager with live preview before save, strict monotonic band validation, stale scorecard marking across configuration version bumps, and explicit re-grade execution.

## Scope decisions recorded before implementation

- **Horizon Profiles**:
  - Distinct profiles for `INTRADAY`, `SWING`, `POSITIONAL`, and `INVESTMENT` trading horizons.
- **Strict Monotonic Band Validation**:
  - Higher-is-better metrics (Sharpe, Profit Factor, Win Rate %, Calmar) require $E > G > A > P$.
  - Lower-is-better metrics (Max Drawdown %) require $E < G < A < P$.
  - Non-monotonic bands or inverted thresholds trigger validation errors and block save.
- **Preview Before Save**:
  - Real-time comparison showing how benchmark strategies grade under current active config vs. modified draft thresholds.
- **Stale Scorecard Lifecycle & Explicit Re-grade Invariant**:
  - Saving a new configuration increments the config version (e.g. `v1.0` -> `v1.1`).
  - Scorecards evaluated against older versions are marked `STALE`, preserving historical auditability.
  - Automatic silent re-grading of historical scorecards is forbidden; re-grading requires an explicit user action (`⚡ Re-Grade Scorecards`).
- **Widget Registry Integration**:
  - `GradingThresholdsWidget` registered in `widgetRegistry` under category `analytics`.

## Required deliverables

1. `frontend/src/grading/types.ts` — Type definitions for horizon profiles, metric thresholds, validation errors, and scorecards.
2. `frontend/src/grading/validator.ts` — Strict monotonic band validator and error reporters.
3. `frontend/src/grading/engine.ts` — Grading evaluation, live preview generator, stale scorecard marker, and explicit re-grade runner.
4. `frontend/src/widgets/builtin/GradingThresholdsWidget.tsx` — Interactive thresholds manager with live preview, save, and re-grade controls.
5. `frontend/src/widgets/builtin/index.ts` — Registration of `gradingThresholdsDefinition`.
6. `frontend/src/grading/validator.test.ts`, `engine.test.ts`, and `GradingThresholdsWidget.test.tsx` — Unit and integration tests.
7. `docs/qa/acceptance/F3.11.md` — Acceptance contract.

## Acceptance scenarios

### B1 — Live preview before save
- Shows real-time grade & score recalculation for a reference strategy when draft thresholds change before committing.

### B2 — Strict monotonic band validation
- Rejects non-monotonic thresholds (e.g. Excellent lower than Good for Sharpe, or Excellent higher than Good for Max Drawdown).

### B3 — Stale scorecard marking on version change
- Saving an updated configuration marks existing scorecards as `STALE`.

### B4 — Explicit re-grade execution only
- Historical scorecards retain old grades until explicit user re-grade trigger is clicked.
