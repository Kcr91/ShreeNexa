# F3.4 Acceptance Contract — Stock Strategy Backtest Runner and Persistence

## Feature

End-to-end stock strategy backtest execution runner completing the first full vertical slice (`StrategyIR` → `VectorStrategyCompiler` → `SimClock` / `HistoricalDataSource` → `SimBroker` with `IndianCostCalculator` → Portfolio Accounting → Metrics Engine → Persistence & Audit Trails).

## Scope decisions recorded before implementation

- **Vertical Slice Integration**:
  - `StockStrategyBacktestRunner`: Coordinates the execution lifecycle consuming `StrategyIR` schema definitions.
  - Sizing models: `FixedQuantity`, `FixedNotional`, `PercentEquity`.
  - Realistic transaction accounting: Each executed fill is priced through `SimBroker` (with slippage) and taxed through `IndianCostCalculator` (Brokerage, STT, Exchange Txn, SEBI, Stamp Duty, GST).
- **Core Performance Metrics**:
  - Computes Total Return, CAGR, Max Drawdown, Sharpe Ratio, Sortino Ratio, Calmar Ratio, Win Rate, Profit Factor, Trade Count, and Cost Summary.
- **Audit & Provenance**:
  - Every `BacktestResult` records git `engine_commit`, random `seed`, exact `StrategyIR` snapshot, execution timestamps, complete trade ledger, and daily/bar equity curve.
- **Reproducibility Guarantee**:
  - Identical `StrategyIR`, data input, and seed produces byte-for-byte identical results and metrics.

## Acceptance scenarios

### B1 — Buy and hold manual reconciliation
- Runs Buy-and-Hold on 30 daily bars of stock data; asserts trade entry, final exit, costs, and final portfolio equity match manual spreadsheet calculations.

### B2 — Intraday SMA crossover strategy manual reconciliation
- Runs SMA crossover strategy with entry, stop loss, and exit rules; verifies exact trade fill timing (next-bar open), Indian taxes applied to every fill, and metrics reconciliation.

### B3 — Determinism and byte-identical reproducibility
- Running two backtest runs with identical config and data yields identical metrics, trade counts, and equity curves.
