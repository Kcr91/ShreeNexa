# F12.2 Acceptance Contract: Live Order Update WebSocket, Postback Ingestion, Deduplication, Sequence Gaps, and Reconciliation

## Feature Definition
- **Feature ID**: F12.2
- **Name**: Live Order Update WebSocket, postback ingestion, deduplication, sequence gaps, and reconciliation.
- **Dependencies**: F7.1, F7.2, F7.3, F12.1
- **Proof Requirement**: Duplicate/lost/out-of-order events converge to broker truth without duplicate fills.

## Invariants & Acceptance Criteria

1. **Live Order Update Stream Protocol (`backend/app/dhan/order_stream.py`)**:
   - Connects to DhanHQ Order Update WebSocket endpoint: `wss://api-order-update.dhan.co`.
   - Sends authorization payload with `MsgCode: 42`, `ClientId`, `Token`, and `UserType: "SELF"`.
   - Parses incoming `order_alert` messages into typed `DhanOrderUpdateEvent`.
   - Exposes fallback postback ingestion model `DhanPostbackPayload` for webhook delivery.

2. **Deduplication & Idempotent Fill Invariant (`backend/app/engine/order_reconciler.py`)**:
   - Multiple identical WebSocket packets or concurrent WebSocket + Postback events for the same order transition are deduplicated based on unique event fingerprint `(order_no, status, traded_qty, last_updated_time)`.
   - Partial or complete fills are applied idempotently. Repeated fill alerts for the same cumulative `traded_qty` do **not** generate duplicate execution fills or skew portfolio balances.

3. **Out-of-Order Events & Gap Detection**:
   - Monotonically tracks execution state transitions (`PENDING` -> `TRIGGERED` / `PART_TRADED` -> `TRADED` / `CANCELLED`).
   - If an out-of-order event arrives (e.g. `TRADED` before `PENDING`, or a sudden skip in traded quantity), the reconciler triggers an immediate broker truth query (`DhanBroker.get_order_by_id`) to converge on the authoritative broker state.

4. **Offline Mock Stream Testability & Zero Secret Exposure**:
   - Stream connection, authentication formatting, and recon logic are 100% testable offline via injectable mock stream sources.
   - Authentication tokens are redacted from all stream logging and exception messages.

## Required Deliverables
1. `backend/app/dhan/order_stream.py` — Typed models and stream client for Dhan order updates & postbacks.
2. `backend/app/engine/order_reconciler.py` — Deduplication engine, fill idempotency tracker, and state gap reconciler.
3. `backend/tests/unit/test_dhan_order_stream.py` — Unit tests for authentication payload, packet parsing, and postback validation.
4. `backend/tests/unit/test_order_reconciler.py` — Proof test suite verifying duplicate/lost/out-of-order events converge to broker truth without duplicate fills.
