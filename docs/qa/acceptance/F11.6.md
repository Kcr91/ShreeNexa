# F11.6 Acceptance Contract: Isolated Sandbox Stack and Live Order Prevention

## Feature Definition
- **Feature ID**: F11.6
- **Name**: Isolated sandbox ports, database schema, Redis database, read-only warehouse, and hard-wired PaperBroker.
- **Dependencies**: F9.1, F9.2, F9.3, F9.4, F9.5, F9.6, F11.4, F11.5
- **Proof Requirement**: Sandbox has no credentials or network/code path capable of placing a live order.

## Invariants & Acceptance Criteria

1. **Sandbox Environment Architecture (Section 14.4)**:
   - The sandbox provides a physically isolated runtime environment ensuring that test tasks, automated runs, and experimental strategies cannot touch live trading state or place real orders.
   - **Network Ports**:
     - Live default ports: API (8000), Engine (8001), Feedd (8002).
     - Sandbox ports: API (8080), Engine (8081), Feedd (8082), or dynamically allocated isolated high ports.
   - **Postgres Database Schema**:
     - Authoritative schema is strictly isolated with `sandbox_*` prefix (e.g. `sandbox_trading`, `sandbox_paper`).
     - Live schemas (`public`, `trading_live`) are completely barred and inaccessible from the sandbox DB connection pool.
   - **Redis Cache & Coordination**:
     - Operates strictly on an isolated database index (e.g. `db=15`), segregated from live runtime state (`db=0`).
   - **DuckDB Historical Warehouse**:
     - Mounted strictly in **read-only mode** (`read_only=True`). Any write, insert, create table, or drop operation raises a read-only database error.
   - **Broker Hard-Wiring**:
     - Strictly hard-wired to `PaperBroker`. The sandbox environment has zero code path or instantiation path to `DhanBroker` or live broker interfaces.
     - Any invocation or configuration attempting to instantiate a live broker in sandbox mode immediately raises `SandboxLiveOrderDisabledError`.
   - **Credential Stripping**:
     - Live order placement tokens, interactive trading tokens, or private trading secrets are completely stripped.
     - The sandbox environment receives either data-only tokens or synthetic test fixtures.

2. **Proof Invariants (Physical Impossibility of Live Order Placement)**:
   - **No Live Code Path**: Calling any order placement dispatch in sandbox mode routes to `PaperBroker` sim fills only. Direct references to `DhanBroker` in sandbox raise `SandboxLiveOrderDisabledError`.
   - **No Live Credentials**: Sandbox credential provider redacts order-placement keys and verifies absence of interactive trading tokens.
   - **Read-Only Warehouse**: DuckDB connection factory rejects write queries with `ReadOnlyWarehouseViolationError`.
   - **Schema Segregation**: Database connection manager enforces `SET search_path TO sandbox_...`.

3. **REST API Interface**:
   - `GET /api/v1/feature-builder/sandbox/status`: Inspect sandbox isolation parameters (ports, schema, redis db, broker type).
   - `POST /api/v1/feature-builder/sandbox/verify-isolation`: Runs automated self-test validating read-only warehouse, lack of live broker path, and absence of live credentials.

4. **Quality Gates & Boundary Compliance**:
   - Zero edits to protected paths (`backend/app/engine/risk.py`, `backend/app/engine/broker.py`, `backend/app/dhan/orders.py`, `backend/tests/parity/`).
   - Strict typing with `mypy backend --strict`.
   - Full linter cleanliness with `ruff check .`.
