# F7.2 Acceptance Contract — Feed Subscription Manager Across Connection Budget

## Feature

Subscription manager across the connection budget, including priority, batching, unsubscribe, reconnect, and resubscribe.

## Scope decisions recorded before implementation

- **Socket Capacity & Budget Coordination**:
  - Leverages `ConnectionBudgetManager` (from `F0.9`) to acquire and release WebSocket leases.
  - Strict ceiling: each socket holds at most 5,000 subscribed instruments.
  - Overall ceiling: governed by active feed socket leases ($N \times 5,000$, default up to 25,000 across 5 sockets).
- **Batching Wire Constraint**:
  - Dhan API limits each subscription/unsubscription request to at most 100 instruments (`MAX_INSTRUMENTS_PER_MESSAGE = 100`).
  - Outbound subscribe and unsubscribe operations are automatically chunked into batches of $\le 100$.
- **Priority-Driven Subscription & Preemption**:
  - Priority levels: `CRITICAL` (0), `HIGH` (1), `MEDIUM` (2), `LOW` (3).
  - Multiple widgets/strategies can request the same instrument; highest priority wins.
  - When connection budget is saturated, `CRITICAL`/`HIGH` subscriptions preempt `LOW` priority subscriptions.
- **Lifecycle, Reconnect, and Resubscription**:
  - When a socket drops and recovers, the subscription manager generates ordered resubscription batches for that socket.
  - Critical instruments are dispatched first to minimize telemetry gap for open positions.
- **Health Telemetry**:
  - Tracks per-socket state, subscribed count, reconnect count, and last packet timestamp.
  - Prepared for Redis hot cache publishing (F7.3).

## Acceptance scenarios

### E1 — Message batching constraint ($\le 100$)
- Subscribing 350 instruments produces exactly 4 batches (100, 100, 100, 50).
- Subscribing 100 instruments produces exactly 1 batch of 100.
- No outbound message ever contains more than 100 instruments.

### E2 — Socket capacity limit ($\le 5,000$)
- A single socket accepts up to 5,000 instruments.
- The 5,001st instrument automatically spills over to a second socket (acquired from budget manager).
- No socket ever exceeds 5,000 instruments.

### E3 — Deduplication & multi-subscriber reference counting
- If Widget A subscribes to Reliance (`NSE_EQ:2885`, `LOW`) and Widget B subscribes to Reliance (`HIGH`), only 1 wire subscription occurs, promoted to `HIGH`.
- When Widget A unsubscribes, the subscription remains active because Widget B still needs it.
- When Widget B unsubscribes, the instrument is batched for unsubscription and removed.

### E4 — Reconnect & automatic resubscription
- When a socket disconnects and transitions to reconnecting/connected, resubscription batches are generated for all its instruments in priority order (`CRITICAL` first).

### E5 — Hypothesis property test
- Property test verifies that across randomized operation sequences, neither the 5,000/socket nor the 100/message limit is ever breached.
