# F12.6 Acceptance Contract: Immutable Audit Trail of Signals, Risk Decisions, Orders, Reconciliation, and Kill-Switch Events

## Feature Definition
- **Feature ID**: F12.6
- **Name**: Immutable audit of every signal, filter, risk decision, order request, response, update, reconciliation, override, and kill-switch event.
- **Dependencies**: F12.1, F12.2, F12.3, F12.4, F12.5
- **Proof Requirement**: One trade can be reconstructed end to end; sensitive values are redacted; audit tampering is detectable.

## Invariants & Acceptance Criteria

1. **Tamper-Evident Cryptographic Hash Chain (`backend/app/engine/audit.py`)**:
   - Every recorded audit event includes:
     - `event_seq`: Monotonically increasing sequence number.
     - `prev_hash`: SHA-256 hash of the immediately preceding audit event in the chain (genesis event starts with `0` * 64).
     - `hash`: Cryptographic SHA-256 hash computed over `(prev_hash, event_seq, event_type, timestamp, correlation_id, canonical_payload)`.
   - Any modification, insertion, deletion, or reordering of logged audit entries invalidates the chain and is detected by `verify_chain()`, pointing directly to the corrupted sequence number.

2. **End-to-End Trade Lifecycle Reconstruction**:
   - Using a single `correlation_id` (or `order_id`), the audit ledger reconstructs the complete chronological lifecycle:
     1. `SIGNAL_GENERATED`
     2. `RISK_DECISION` (Approved / Rejected)
     3. `ORDER_SUBMITTED`
     4. `ORDER_RESPONSE`
     5. `ORDER_UPDATE` (Execution fill)
     6. `RECONCILIATION_EVENT`
     7. `OPERATOR_OVERRIDE` / `KILL_SWITCH_EVENT` (if applicable)

3. **Strict Redaction of Sensitive Data**:
   - All audit payloads are processed through an automated redaction scrubber:
     - Sensitive keys (`access_token`, `token`, `password`, `secret`, `authorization`, `cookie`) are scrubbed and replaced with `"[REDACTED]"`.
     - Client IDs are masked to protect account privacy (`11000****78`).
   - No raw credentials or secret tokens can ever enter the immutable ledger.

4. **Zero Real Broker Order Placement in Tests**:
   - All test suites run against mock event streams and synthetic trade cycles. No live broker calls occur.

## Required Deliverables
1. `backend/app/engine/audit.py` — Audit ledger, event hashing, redaction scrubber, and lifecycle reconstruction.
2. `backend/tests/unit/test_audit_ledger.py` — Unit and proof tests verifying tamper detection, sensitive value redaction, and end-to-end trade lifecycle reconstruction.
