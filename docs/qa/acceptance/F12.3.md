# F12.3 Acceptance Contract: Live Order Ticket with Explicit Mode, Estimated Charges/Margin, Confirmations, Validation, and Status Uncertainty

## Feature Definition
- **Feature ID**: F12.3
- **Name**: Live order ticket with explicit mode, estimated charges/margin, confirmations, validation, and status uncertainty.
- **Dependencies**: F4.2, F4.3, F8.6, F12.1, F12.2
- **Proof Requirement**: Playwright cannot submit accidentally; paper/live are unmistakable; uncertain order state blocks blind retry.

## Invariants & Acceptance Criteria

1. **Unmistakable Mode Distinction & Confirmation Gate**:
   - Every order submission requires an explicit `mode: "PAPER" | "LIVE"`.
   - Default mode is always `"PAPER"`.
   - Live mode requires an explicit user confirmation flag (`confirmation_acknowledged: true`).
   - If the system live activation gate is disabled (`is_live_enabled == false`), live submission returns HTTP 403 Forbidden with `"Live trading is disabled"`.

2. **Charges & Margin Estimation API**:
   - `POST /api/v1/orders/ticket/estimate` accepts order parameters and calculates breakdown:
     - Brokerage (Dhan flat ₹20 or 0.03% whichever is lower for equity intraday/futures; ₹20 flat for options; ₹0 for equity delivery).
     - STT / CTT based on Indian tax schedule.
     - Exchange transaction charges (NSE/BSE).
     - GST (18% on Brokerage + Exchange charges + SEBI fees).
     - Stamp duty (SEBI schedule).
     - Total statutory charges and net required margin.

3. **Status Uncertainty & Blind Retry Prevention**:
   - When an order enters `PENDING_BROKER_CONFIRMATION` due to upstream network uncertainty or broker timeout, subsequent submission attempts with the same correlation ID or active uncertain state are blocked from re-placement.
   - Status endpoint `GET /api/v1/orders/ticket/status/{order_id}` reports uncertain status and directs client to wait for WebSocket/recon instead of retrying blindly.

4. **Zero Live Orders during Automated Testing**:
   - Automated tests run against mock transports and local paper engines. Zero live money or orders are permitted.

## Required Deliverables
1. `backend/app/api/orders.py` — FastAPI router for order ticket estimation, placement, and status.
2. `backend/app/main.py` — Register `/api/v1/orders/ticket` route.
3. `frontend/src/order/execution.ts` & `frontend/src/order/types.ts` — Order ticket logic with status uncertainty and confirmation flags.
4. `backend/tests/unit/test_order_ticket_api.py` — Comprehensive API test suite covering estimation, validation, live gating, and retry prevention.
5. `frontend/src/order/execution.test.ts` — Frontend tests verifying confirmation gating and retry prevention.
