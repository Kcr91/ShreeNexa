# F7.4 Acceptance Contract — Browser WebSocket Fan-Out and Resync

## Feature

Browser WebSocket fan-out with snapshots, deltas, backpressure, reconnect/resync, and authorization boundary.

## Scope decisions recorded before implementation

- **Market-data truth and freshness**:
  - Every browser quote carries an explicit state: `LIVE`, `MARKET_CLOSED`,
    `STALE`, `UNAVAILABLE`, or `ERROR`.
  - `LIVE` requires a connected upstream feed and a fresh exchange/API timestamp.
    A running process or open browser socket alone never qualifies as live.
  - Outside the instrument's trading session, the last verified Dhan close may be
    served as `MARKET_CLOSED` with its source timestamp. If no verified close is
    available, the response is `UNAVAILABLE` or `ERROR` rather than a fabricated
    value.
  - Seeded, simulated, generated, or silent fallback market values are forbidden
    in production and development UI paths.
  - Previous-close packets update the comparison reference and never overwrite
    LTP. Percentage change is derived only when Dhan has supplied both values.

- **Process Ownership (ADR-0002 & ADR-0003)**:
  - The `api` process owns the browser WebSocket fan-out endpoint.
  - Frontend browsers connect to `/api/v1/feed/ws` or `/ws/market` with session authentication.
  - `api` reads snapshots from `feedd`'s Redis hot cache (`HotCache`) and fans out streaming market ticks.
- **Authorization Boundary**:
  - Accepted live-data browser connections use the same-origin HttpOnly
    `shreenexa_session` cookie representing a session created after master-password
    and TOTP verification. A valid programmatic master-session token may be supplied
    as the existing query parameter.
  - Unauthenticated connections are rejected with close code `4401`; development
    demo sessions are rejected with `4403` and cannot read live Dhan feed or
    heatmap routes.
- **Snapshots & Deltas**:
  - Upon subscription or `resync` request, an immediate full state snapshot (`quotes`, `depth`, `oi`) is fetched from `HotCache` and sent to the client.
  - Streaming updates from the feed are dispatched as incremental deltas or ticks to interested subscribers.
  - Browser subscriptions preserve the canonical exchange segment and security ID;
    indices are never subscribed under the NSE-equity segment.
- **Backpressure & Slow-Client Protection (Core Invariant)**:
  - Outbound message queues are strictly bounded (`maxsize`).
  - Outbound dispatch uses non-blocking enqueue (`put_nowait`).
  - If a slow client cannot drain its queue, deltas are conflated or dropped, `dropped_messages_count` is incremented, and `is_slow` is flagged.
  - **Invariant**: A slow or stalled client cannot block feed ingestion or degrade throughput for other clients.
- **Reconnect & Resync**:
  - Clients can send `{"action": "resync"}` at any time to recover missed packets and receive a fresh consistent snapshot.
- **Three-Client Consistency Test**:
  - Minimum 3 concurrent clients (e.g., 2 fast clients, 1 slow/stalled client).
  - Verifies feed ingestion throughput is unimpeded.
  - Verifies fast clients receive all data consistently.
  - Verifies slow client triggers backpressure protection without cross-client interference.

## Required deliverables

1. `backend/app/api/ws.py` — `MarketDataFanoutManager`, `ClientSession`, backpressure policies, and subscription routing.
2. `backend/app/api/feed.py` — WebSocket endpoint `/api/v1/feed/ws` integrating `MarketDataFanoutManager` and `HotCache`.
3. `docs/qa/acceptance/F7.4.md` — Acceptance contract.
4. `backend/tests/unit/test_market_ws_fanout.py` — Unit and integration tests covering:
   - Three-client consistency test.
   - Slow client backpressure without blocking feed ingestion.
   - Snapshot delivery on initial subscribe and explicit resync.
   - Incremental delta streaming to subscribed clients.
   - Authorization boundary validation.
