# F1.1 Acceptance Contract — Immutable DuckDB/Parquet Bar Store

## Feature

Implement immutable DuckDB/Parquet bar store with typed schema, partition manifest, atomic writes, correction workflow, rollback capabilities, and partition-pruned DuckDB read API.

## Scope decisions recorded before implementation

- **Immutable Data Layout & Partition Hierarchy**:
  - Default data root is `<repository>/data` with `.shreenexa-data-root.json` ownership marker.
  - Published versions reside under `data/warehouse/versions/<warehouse_version>/`.
  - Partition structure: `bars/segment=<exchange_segment>/year=<YYYY>/month=<MM>/part-*.parquet`.
  - Manifests reside under `data/warehouse/manifests/manifest-<warehouse_version>.json`.
  - Active version is pointed to by atomically replaced `data/warehouse/current.json`.
- **Atomic Publication Invariant**:
  - `worker` writes to `data/staging/<warehouse_version>/` first.
  - All partition files are validated for schema adherence, row counts, min/max timestamps, and SHA-256 checksums.
  - Completed staging directory is atomically moved to `data/warehouse/versions/<warehouse_version>/`.
  - Manifest is written once and frozen.
  - `data/warehouse/current.json` is updated via atomic file replacement (`.tmp` to `.json`).
  - Interrupted writes leave `current.json` untouched and never expose partial partitions to readers.
- **Correction & Rollback**:
  - Corrections publish a new version ID recording `parent_version` and `corrections: [{reason, replaces_partition_digest}]`.
  - Rollback verifies prior version integrity and updates `current.json` with an incremented `pointer_generation` without mutating either version.
- **Read API & Partition Pruning**:
  - `WarehouseReader` pins the current manifest and queries Parquet partitions via DuckDB.
  - Queries filter by `exchange_segment`, `symbol`, `start_time`, `end_time`, pruning unneeded partitions.

## Acceptance scenarios

### B1 — Data root initialization and marker
- Verifies `.shreenexa-data-root.json` ownership marker in the data root.
- Ensures staging, warehouse, and manifests subdirectories are created cleanly.

### B2 — Partition writing, hashing, and atomic publication
- Writes synthetic OHLCV bars into partitioned Parquet files.
- Generates canonical manifest recording exact SHA-256 hashes, row counts, and date ranges.
- Atomically replaces `current.json` pointer with `pointer_generation = 1`.

### B3 — DuckDB read round-trip and partition pruning
- `WarehouseReader` queries the published version via DuckDB.
- Retrieves exact OHLCV bars for specific symbols and date ranges.
- Confirms partition pruning only scans relevant segment/year/month files.

### B4 — Interrupted write safety
- Simulates write failure or abort during staging before pointer update.
- Verifies `current.json` remains pointing to previous version (or empty) with no partial data exposed to readers.

### B5 — Correction workflow and rollback
- Publishes a corrected partition in a new warehouse version.
- Verifies lineage tracking in manifest (`parent_version`, `corrections`).
- Executes rollback to previous version, verifying incremented pointer generation and restored data views.
