# F11.3 Acceptance Contract: Codex Task Runner, Events, Cancellation, and Durable State

## Feature Definition
- **Feature ID**: F11.3
- **Name**: Codex task runner with bounded fresh task context, structured events, browser stream, cancellation, and durable state.
- **Dependencies**: F11.1, F11.2
- **Proof Requirement**: Interrupt/restart resumes from git/state, not conversation history; auth/usage errors are explicit.

## Invariants & Acceptance Criteria

1. **Bounded Fresh Task Context**:
   - Each runner task operates on an isolated context consisting strictly of:
     - Target `FeatureSpec` from F11.1.
     - Allocated worktree and branch from F11.2.
     - Current Git commit SHA and status.
   - Context is strictly bounded to prevent token bloating and eliminate reliance on conversation memory.

2. **Durable Task Journaling**:
   - Persists execution state to disk (`build/tasks/<task_id>/state.json`).
   - Records:
     - `task_id`, `feature_id`, `worktree_id`.
     - `status`: `PENDING`, `RUNNING`, `INTERRUPTED`, `CANCELLED`, `COMPLETED`, `FAILED`.
     - Step sequence, checkpoints, timestamps, and Git HEAD SHA.

3. **Interrupt & Resume from Git/State (Proof Requirement)**:
   - When a task is interrupted (e.g. process termination or simulated crash):
     - It does NOT rely on in-memory chat conversation history.
     - `resume_task(task_id)` reconstructs task execution context strictly by loading `state.json` and reconciling with active worktree Git status.
     - Execution resumes from the exact recorded checkpoint step.

4. **Explicit Auth & Usage Errors (Proof Requirement)**:
   - Differentiates and raises explicit typed exceptions:
     - `CodexAuthenticationError`: Missing, invalid, or expired API keys/tokens.
     - `CodexQuotaExceededError`: Usage caps, rate limit exhaustion, or insufficient credits.
   - Errors are explicitly surfaced with structured metadata, never obscured or swallowed as generic exceptions.

5. **Structured Event Stream & Cancellation**:
   - Emits structured lifecycle events (`TASK_STARTED`, `STEP_PROGRESSED`, `TASK_CANCELLED`, `TASK_COMPLETED`, `TASK_FAILED`).
   - Real-time browser streaming via Server-Sent Events (`text/event-stream`).
   - Supports clean task cancellation terminating active execution and emitting cancellation events.

6. **REST API Interface**:
   - `POST /api/v1/feature-builder/tasks`: Initiate a new task runner execution.
   - `GET /api/v1/feature-builder/tasks/{task_id}`: Inspect task status, checkpoint, and history.
   - `POST /api/v1/feature-builder/tasks/{task_id}/cancel`: Cancel a running task.
   - `POST /api/v1/feature-builder/tasks/{task_id}/resume`: Resume an interrupted task from git/state.
   - `GET /api/v1/feature-builder/tasks/{task_id}/events`: SSE endpoint for real-time event streaming.
   - `GET /api/v1/feature-builder/tasks`: List tasks with status filters.

7. **Quality & Boundary Gates**:
   - `mypy backend --strict`, `ruff check .`, `pytest`, frontend checks, and manifest validation.
   - Zero modifications to protected paths.
