# F6.5 Acceptance Contract — Versioned Regime Detectors and Enforced Walk-Forward Switching

## Feature

Versioned market regime detectors, point-in-time look-ahead protection, G1/G2 parity for RegimeNode, and enforced walk-forward evidence validation for headline metrics.

## Scope decisions recorded before implementation

- **Look-Ahead Prevention (Strict Invariant)**:
  - At any bar index $t$, the regime state must depend solely on historical bars $0 \le s \le t$.
  - Truncation invariant: Evaluating the detector on slice $[0..t]$ must yield the exact same regime state at bar $t$ as evaluating on full dataset $[0..T]$.
- **Versioned Detectors**:
  - Detectors must expose a version identifier (e.g. `vol_v1`, `trend_v1`), detector name, and list of supported states.
  - Registry pattern allows registering custom and versioned detectors.
- **G1/G2 Equivalence for RegimeNode**:
  - `VectorStrategyCompiler` (G1) and `IncrementalStrategyEngine` (G2) evaluate `RegimeNode` to bit-for-bit identical boolean masks across historical bars.
- **Enforced Walk-Forward Validation**:
  - Strategies employing regime conditioning risk severe backtest overfitting.
  - Publishing official headline backtest metrics (Scorecard grading, Sharpe, CAGR) for any strategy containing `RegimeNode` is strictly **refused** unless accompanied by verified walk-forward analysis evidence with valid positive walk-forward efficiency.

## Required deliverables

1. `backend/app/strategy/regime.py` — Versioned regime detector base classes, built-in detectors (`vol_v1`, `trend_v1`), detector registry, and walk-forward verification guard.
2. Updates to `backend/app/strategy/compiler.py` — Evaluate `RegimeNode` using registered regime detectors.
3. Updates to `backend/app/strategy/incremental.py` — Incremental point-in-time `RegimeNode` streaming evaluation.
4. `backend/app/strategy/__init__.py` — Package exports.
5. `backend/tests/unit/test_strategy_regime.py` — Unit tests for look-ahead prevention, G1/G2 parity, and walk-forward enforcement.
6. `docs/qa/acceptance/F6.5.md` — Acceptance contract.

## Acceptance scenarios

### E1 — Look-ahead prevention and point-in-time invariant
- Verifies that evaluating a regime detector on truncated subsets produces identical regime labels at time $t$ compared to the full dataset.

### E2 — Versioned regime detector registry
- Verifies detector registration, version retrieval, and state validation.

### E3 — G1/G2 parity for RegimeNode
- Runs a strategy with `RegimeNode` across multi-bar historical dataset.
- Verifies bit-for-bit parity between G1 (vectorized) and G2 (incremental).

### E4 — Headline metrics refused without walk-forward evidence
- Evaluates a regime-conditioned strategy; verifies that headline metrics scorecard generation fails with `WalkForwardEvidenceRequiredError` when walk-forward evidence is absent or invalid.
- Verifies that providing valid walk-forward evidence permits publishing verified headline scorecard metrics.
