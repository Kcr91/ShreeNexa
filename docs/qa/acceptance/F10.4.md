# F10.4 Acceptance Contract: SIP Planning and Calendar/Threshold Rebalancing Proposals

## Feature Definition
- **Feature ID**: F10.4
- **Name**: SIP planning and calendar/threshold rebalancing proposals. No automatic orders.
- **Dependencies**: F1.5, F10.1, F10.2, F10.3
- **Proof Requirement**: Cashflow/TWR separation; G2; proposal totals respect cash and configured limits.

## Invariants & Acceptance Criteria

1. **SIP Planning Engine**:
   - Defines recurring investment baskets with target weights across equity, ETF, and debt instruments.
   - Computes whole-lot share allocations for periodic instalments given latest CMPs and remaining unallocated cash.
   - Supports annual step-up SIP schedule calculation (e.g. +10% annual increase).

2. **Calendar & Threshold Rebalancing Proposals**:
   - Computes target portfolio drift: $\Delta w_i = w_{i, \text{current}} - w_{i, \text{target}}$.
   - Triggers rebalance proposals based on:
     - Calendar frequency: Quarterly, Semi-Annually, Annually.
     - Threshold/Band trigger: When $|\Delta w_i| > \text{tolerance\_band\_pct}$ (e.g. 5.0%).
   - Generates discrete proposal items: `BUY` for underweight, `SELL` for overweight.
   - Inflow-only rebalance mode: Directs fresh SIP capital to underweight assets to bring portfolio into alignment without selling or incurring capital gains tax.

3. **Strict Safety Invariants (No Automatic Orders & Limit Enforcement)**:
   - **No automatic orders**: All generated output is marked `status="PROPOSED"`. The engine strictly generates proposals for review and NEVER transmits orders to the broker or engine.
   - **Cash & limit respect**: Total proposed purchases must not exceed available cash. Individual positions must respect `max_allocation_per_trade`.

4. **Cashflow / TWR Separation**:
   - Computes Time-Weighted Return (TWR) by chaining holding-period sub-returns across cashflow injection dates:
     $$TWR = \prod_{t=1}^k (1 + r_t) - 1$$
   - Eliminates cashflow timing distortions inherent in MWR/XIRR, isolating manager performance from client deposit/withdrawal timing.

5. **REST API Interface**:
   - `POST /api/v1/investing/sip/plan`: Generate whole-share SIP allocation from budget and target weights.
   - `POST /api/v1/investing/rebalance/proposal`: Generate rebalancing proposal respecting cash limits and threshold bands.
   - `POST /api/v1/investing/performance/twr`: Compute Time-Weighted Return with cashflow separation.

6. **Quality & Boundary Gates**:
   - `mypy backend --strict`, `ruff check .`, `pytest`, frontend checks, and manifest validation.
   - Zero modifications to protected paths.
