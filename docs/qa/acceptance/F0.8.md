# F0.8 Acceptance Contract — Index Constituent Ingestion and Point-in-Time Membership

## Feature

Build current and historical index-constituent ingestion from scratch using effective intervals `[valid_from, valid_to]`, official source snapshots, committed fallback configuration, manual overrides, and point-in-time date-aware membership queries with visible provenance.

## Scope decisions recorded before implementation

- **Effective Intervals & Point-in-Time Correctness**:
  - `index_constituent` stores `index_name`, `symbol`, `weight`, `sector`, `valid_from`, `valid_to` (NULL for currently active), `source_date`, and `source` (`'nse_archive'`, `'fallback'`, `'manual'`, `'official_snapshot'`).
  - Primary Key is `(index_name, symbol, valid_from)`.
  - Check constraint `CHECK (valid_to IS NULL OR valid_to >= valid_from)`.
  - Point-in-time query for date $D$: `valid_from <= D AND (valid_to IS NULL OR valid_to >= D)`.
  - Prevents look-ahead bias and survivorship bias during historical backtesting.
- **Committed Fallback & Provenance**:
  - Committed YAML snapshot in `config/index_constituents_fallback.yaml` provides verified baselines for `NIFTY 50`, `NIFTY BANK`, and `NIFTY IT`.
  - If upstream source is unreachable, fallback snapshots are ingested with `source='fallback'` and explicit `source_date`, remaining completely non-fatal.
- **Manual Overrides**:
  - Administrative/research overrides can be applied with `source='manual'`, overriding previous intervals.
- **REST API Contract**:
  - List available indices, get constituents with weights/sectors as of any historical date, and query point-in-time symbol membership.

## Acceptance scenarios

### B1 — Database migration reversibility
- `alembic upgrade head` creates the `index_constituent` table with constraints and indexes.
- `alembic downgrade -1` cleanly drops the table and index.

### B2 — Fallback ingestion with provenance
- Ingesting committed fallback configuration populates `NIFTY 50`, `NIFTY BANK`, and `NIFTY IT` with `source='fallback'` and non-null `source_date`.

### B3 — Date-aware point-in-time membership
- Querying index membership on a date before a stock joined returns `False`.
- Querying index membership during the stock's tenure returns `True` with its assigned weight.
- Querying index membership after exclusion returns `False`.

### B4 — Manual overrides
- Applying a manual addition or deletion modifies the active interval with `source='manual'`, recorded in provenance.

### B5 — Graceful handling of missing indices
- Querying an unknown index or date with no recorded constituents returns an empty list without raising 500 errors.

### B6 — REST API contract
- `GET /api/v1/indices` returns distinct available indices.
- `GET /api/v1/indices/{index_name}/constituents?as_of=YYYY-MM-DD` returns list of constituents with provenance.
- `GET /api/v1/indices/{index_name}/membership?symbol=XYZ&as_of=YYYY-MM-DD` returns `{is_member: bool, weight: float, source: str}`.
