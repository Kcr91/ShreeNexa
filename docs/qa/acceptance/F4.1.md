# F4.1 Acceptance Contract — React/TypeScript/Vite Shell, Routing, Theme Tokens, and API Boundary

## Feature

Production React/TypeScript/Vite frontend shell for ShreeNexa Terminal featuring design theme tokens, client-side route navigation, typed API client boundary, error boundaries, loading skeletons, development authentication stub, and real-time Dhan token health banner.

## Scope decisions recorded before implementation

- **Theme Tokens & Design System**:
  - Dark terminal theme with high-contrast palette, Indian market green/red indicators, and typography configured in CSS custom properties.
- **Typed API Client Boundary**:
  - Centralized `apiClient` with base URL configuration, typed error responses, timeout handling, and strict credential redaction in telemetry/logs.
- **Client-Side Routing**:
  - Lightweight declarative route manager supporting `/dashboard`, `/research`, `/screener`, `/pnl`, and `/settings`.
- **Error & Loading Boundaries**:
  - React Error Boundary capturing render faults with user recovery actions.
  - Reusable loading spinners and skeleton loaders.
- **Development Auth & Health Banner**:
  - Development auth context provider exposing active trader session and Dhan token health banner integration.
- **Accessibility & Production Build**:
  - Semantic HTML landmarks (`<header>`, `<nav>`, `<main>`, `<footer>`), unique component IDs, ARIA labels, and clean production bundle creation.

## Required deliverables

1. `frontend/src/theme/tokens.css` & `frontend/src/index.css` — Design system CSS variables and layout styles.
2. `frontend/src/api/client.ts` — Typed HTTP API client.
3. `frontend/src/auth/AuthContext.tsx` — Development authentication stub and provider.
4. `frontend/src/components/Header.tsx`, `Navigation.tsx`, `StatusFooter.tsx`, `ErrorBoundary.tsx`, `LoadingSkeleton.tsx`, `Shell.tsx`.
5. `frontend/src/views/DashboardView.tsx`, `ResearchView.tsx`, `ScreenerView.tsx`, `PnLView.tsx`, `SettingsView.tsx`.
6. `frontend/src/App.tsx` — App root.
7. `frontend/src/App.test.tsx` & `frontend/src/components/Shell.test.tsx` — Component and route unit tests.
8. `docs/qa/acceptance/F4.1.md` — Acceptance contract.

## Acceptance scenarios

### B1 — Production bundle and build cleanliness
- `npm.cmd --prefix frontend run build` completes with zero TypeScript errors, clean bundle hashing, and no secret keys in build output.

### B2 — Shell navigation, route switching, and view mounting
- User can switch routes between Dashboard, Research, Screener, P&L, and Settings with instant state synchronization and active link indication.

### B3 — Error boundary recovery and loading states
- Rendering error in a subcomponent is safely caught by `ErrorBoundary` without crashing the entire terminal shell.
- Loading skeletons render during async data fetching.
