# F9.2 Acceptance Contract — Paper Order Book, Trade Book, Positions, Live MTM, Costs, and Rejection/Reason Display

## Feature

Integrated paper trading blotter displaying paper order book, trade book (fills), open positions with live mark-to-market (MTM), itemized statutory transaction costs, and explicit rejection reason display, backed by an independent accounting fixture that proves UI/API/order/fill/position reconciliation.

## Scope decisions recorded before implementation

- **Paper Order Book (Spec §9.2)**:
  - Working, filled, partially filled, cancelled, and rejected orders.
  - Rejection reasons (`reject_reason`) explicitly rendered with high-visibility badges/tooltips (e.g., "Insufficient funds: required ₹..., available ₹...").
  - One-click order cancellation for active (`ACCEPTED`, `PARTIALLY_FILLED`) orders.
- **Paper Trade Book (Fills)**:
  - Chronological execution ledger showing Fill ID, Order ID, Symbol, Side (BUY/SELL), Quantity, Execution Price, Slippage, and itemized Indian statutory transaction charges.
- **Positions & Live MTM**:
  - Open positions grouped by security, showing Quantity, Average Entry Price, Last Traded Price (LTP), Realized P&L, Unrealized MTM P&L, and Net P&L.
  - Real-time MTM recalculation as price updates stream in.
- **Account Summary & Transaction Costs**:
  - Live portfolio metrics: Cash Balance, Blocked Margin, Realized P&L, Unrealized MTM P&L, Net Equity, and Cumulative Transaction Costs paid.
- **Accounting Reconciliation & Invariance Proof**:
  - Independent accounting fixture verifying:
    $$\text{Cash Balance}_{\text{final}} = \text{Cash Balance}_{\text{initial}} - \sum_{\text{BUY}} (P \times Q + C) + \sum_{\text{SELL}} (P \times Q - C)$$
    $$\text{Realized P&L} = \sum_{\text{closed legs}} (\text{Proceeds} - \text{Cost Basis} - \text{Charges})$$
    $$\text{Unrealized P&L} = \sum_{\text{open positions}} (P_{\text{current}} - P_{\text{entry}}) \times Q$$
  - Discrepancy between UI, API, orders, fills, and position records must be exactly $0.00$.
- **Widget Integration**:
  - Registered built-in `PaperTradingWidget` (`paper_trading_widget`) adhering to `WidgetDefinition` and multi-grid layout system (F4.2, F4.3).
