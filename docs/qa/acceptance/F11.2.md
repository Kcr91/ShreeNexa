# F11.2 Acceptance Contract: Git Worktree Isolation, Branch Ownership, and Path Validation

## Feature Definition
- **Feature ID**: F11.2
- **Name**: Git worktree creation, branch ownership, path validation, cleanup, and recovery.
- **Dependencies**: F11.1
- **Proof Requirement**: Property/acceptance tests prove the runner cannot write outside its worktree.

## Invariants & Acceptance Criteria

1. **Git Worktree Provisioning & Branch Ownership**:
   - Creates isolated Git worktrees under designated isolation paths (`build/worktrees/<task_id>`).
   - Ensures distinct branch ownership: each worktree operates on a dedicated `feature/<feature_id>-<slug>` branch checked out from a validated clean base commit.
   - Prevents multiple worktrees from sharing the same checked-out branch simultaneously.

2. **Strict Worktree Path Containment & Escape Prevention (Proof Requirement)**:
   - Implements rigorous path resolution and containment verification:
     `validate_worktree_path(target_path, worktree_root) -> Path`
   - Prohibits all path escapes:
     - Parent directory traversal (`../`).
     - Absolute paths resolving outside the worktree root.
     - Escapes targeting the main repository working tree.
     - Escapes targeting protected legacy project (`F:\Algotrading`).
     - Escapes targeting operating system directories.
   - Throws explicit `PathEscapeViolationError` on any unauthorized access attempt.

3. **Lifecycle Cleanup & Orphaned Worktree Recovery**:
   - `cleanup_worktree`: Safely tears down the worktree via `git worktree remove` and `git worktree prune`.
   - `recover_orphaned_worktrees`: Audits registered worktrees against running tasks and disk state; cleans up stale or crashed allocations without touching active user work.

4. **REST API Interface**:
   - `POST /api/v1/feature-builder/worktrees`: Create an isolated worktree for a feature spec.
   - `GET /api/v1/feature-builder/worktrees`: List all active worktree allocations.
   - `GET /api/v1/feature-builder/worktrees/{worktree_id}`: Inspect a worktree's path and status.
   - `DELETE /api/v1/feature-builder/worktrees/{worktree_id}`: Remove and cleanup a worktree.
   - `POST /api/v1/feature-builder/worktrees/reconcile`: Reconcile and clean orphaned worktrees.

5. **Quality & Boundary Gates**:
   - `mypy backend --strict`, `ruff check .`, `pytest`, frontend checks, and manifest validation.
   - Zero modifications to protected paths.
