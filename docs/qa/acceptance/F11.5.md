# F11.5 Acceptance Contract: Protected-Path Layered Enforcement and Security Auditing

## Feature Definition
- **Feature ID**: F11.5
- **Name**: Protected-path enforcement for risk, broker, live orders, and parity fixtures at prompt/tool/diff/promotion layers.
- **Dependencies**: F11.2, F11.3, F11.4
- **Proof Requirement**: Attempted protected edit is denied and audited even if one enforcement layer is bypassed.

## Invariants & Acceptance Criteria

1. **Protected Paths Definition**:
   - The authoritative protected paths per `AGENTS.md` and ADR-0011 are:
     - `backend/app/engine/risk.py`
     - `backend/app/engine/broker.py`
     - `backend/app/dhan/orders.py`
     - `backend/tests/parity/` (entire directory and all subfiles)
   - These paths are strictly excluded from automated or unattended edits. Any modification requires a separately scoped, supervised feature with explicit human sign-off.

2. **Four Defense-in-Depth Enforcement Layers**:
   - **Layer 1 (Prompt / Context Guard)**:
     - Detects requests or tasks that target protected paths before code generation or runner startup.
     - Scans prompt instructions, file lists, and spec requests. Rejects tasks attempting to target protected files.
   - **Layer 2 (Tool Execution / File Write Guard)**:
     - Intercepts all file write, edit, replace, move, or delete tool invocations inside the runner or worktree.
     - Enforces path normalization, prevents symlink escapes, parent traversal (`../`), and directory tricks.
     - Immediately raises `ProtectedPathPermissionDeniedError` if a tool targets a protected path.
   - **Layer 3 (Git Diff / Working Tree Guard)**:
     - Performs strict pre-commit diff analysis (`git diff --name-only <base>...<head>` or working tree status).
     - Detects unauthorized modifications even if the tool interceptor was bypassed (e.g. via direct shell execution or script execution).
     - Aborts commit creation and flags security breach.
   - **Layer 4 (Promotion & Fast-Forward Guard)**:
     - Audits candidate commit tree and Git commit object prior to fast-forward merge into `main` or deployment promotion.
     - Rejects promotion and marks task `BLOCKED_SECURITY_VIOLATION` if any commit touches a protected path.

3. **Durable Security Audit Trail**:
   - Every attempted breach across ANY layer is durably recorded in `build/tasks/security_audit.json`:
     - `event_id`: Unique audit identifier.
     - `timestamp`: UTC timestamp.
     - `task_id`: Identifier of the violating task/run.
     - `layer`: The defense layer that detected the violation (`PROMPT`, `TOOL`, `DIFF`, `PROMOTION`).
     - `path`: The exact protected file or directory targeted.
     - `action_taken`: Action executed (e.g. `DENIED_AND_BLOCKED`).
     - `bypassed_layers`: Any layers that were bypassed prior to detection.

4. **Proof Invariant (Bypass Resistance)**:
   - If Layer 1 is bypassed (unflagged prompt), Layer 2 blocks the tool call and logs the audit event.
   - If Layer 2 is bypassed (unintercepted write), Layer 3 blocks the Git diff inspection and logs the audit event.
   - If Layer 3 is bypassed (forced commit), Layer 4 blocks branch promotion / fast-forward merge and logs the audit event.
   - Under no circumstances does an automated edit to a protected path merge into `main`.

5. **REST API Interface**:
   - `POST /api/v1/feature-builder/security/verify-path`: Validates if a target path is protected.
   - `GET /api/v1/feature-builder/security/audit`: Retrieves the security audit event log.
   - `POST /api/v1/feature-builder/security/check-diff`: Evaluates a file list or branch diff against all 4 layers.

6. **Repository Invariants**:
   - Zero modifications to protected paths.
   - Strict typing with `mypy backend --strict`, full linter clean with `ruff check .`, all tests passing.
