# F9.6 Acceptance Contract — Deploy/Pause/Resume/Stop Lifecycle, Engine Ownership, Restart Reconciliation, and Audit Events

## Feature

Forward-testing strategy deployments operate under a complete deploy/pause/resume/stop lifecycle owned by the independent `engine` role, with crash/restart state reconciliation, tamper-evident audit logging, and idempotent controls.

## Scope decisions recorded before implementation

- **Process Independence (ADR-0002, Spec §4.1)**:
  - Strategy deployments are owned, scheduled, and executed within the `engine` runtime role.
  - The `api` process serves as an administrative client; restarting `api` never stops or interferes with active `engine` deployments.
- **Strict Lifecycle State Machine**:
  - Valid States: `CREATED`, `RUNNING`, `PAUSED`, `STOPPED`, `FAILED`.
  - Operations:
    - `deploy`: Transitions from `CREATED` to `RUNNING`, sets up isolated strategy broker and risk limits.
    - `pause`: Transitions `RUNNING` -> `PAUSED`. Halts signal dispatch and new order creation; keeps open positions monitored for stop-loss.
    - `resume`: Transitions `PAUSED` -> `RUNNING`. Resumes signal processing and execution.
    - `stop`: Idempotently transitions (`RUNNING` | `PAUSED`) -> `STOPPED`. Cancels working orders, flattens inventory if configured. Repeated `stop` calls succeed safely without raising errors.
- **Tamper-Evident Audit Event Trail**:
  - Every lifecycle transition generates an immutable `DeploymentAuditEvent` containing:
    - `event_id`, `deployment_id`, `timestamp`, `from_state`, `to_state`, `action`, `actor`, `reason`, `metadata`.
- **Durable Persistence and Crash Recovery**:
  - Deployment configurations, current states, and audit trails persist durably (`DeploymentStore`).
  - Startup reconciliation (`reconcile_on_startup`):
    - Recovers persisted deployments upon process restart.
    - Reconciles working orders and fills against `PaperBroker` and `PaperRepository`.
    - Guarantees zero duplicate fills and zero duplicate order submissions across engine restarts.
- **REST API Endpoints**:
  - `POST /api/v1/paper/deployments`: Deploy strategy to paper engine.
  - `GET /api/v1/paper/deployments`: List deployments.
  - `GET /api/v1/paper/deployments/{deployment_id}`: Get status and active state.
  - `POST /api/v1/paper/deployments/{deployment_id}/pause`: Pause execution.
  - `POST /api/v1/paper/deployments/{deployment_id}/resume`: Resume execution.
  - `POST /api/v1/paper/deployments/{deployment_id}/stop`: Idempotently halt deployment.
  - `GET /api/v1/paper/deployments/{deployment_id}/audit`: Query audit history.

## Required deliverables

1. `backend/app/paper/lifecycle.py` — Complete deployment lifecycle state machine, `DeploymentManager`, `DeploymentStore`, and `DeploymentAuditEvent` trail.
2. `backend/app/api/paper.py` — REST endpoints for deployment lifecycle operations and audit trail.
3. `backend/app/paper/__init__.py` — Package exports for deployment models and manager.
4. `backend/tests/unit/test_paper_deployment_lifecycle.py` — Unit tests verifying lifecycle transitions, API operations, process independence, idempotency of stop, restart recovery, and audit logging.
5. `docs/qa/acceptance/F9.6.md` — Acceptance contract.
