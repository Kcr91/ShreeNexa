# F7.1 Acceptance Contract — Dhan Live-Feed WebSocket Client and Binary Packet Parser

## Feature

Dhan live-feed WebSocket client, binary packet parser, heartbeat, reconnect state machine, and captured golden packets.

## Scope decisions recorded before implementation

- **Binary Wire Protocol**:
  - Dhan HQ Live Market Feed uses binary message encoding in Little Endian (`<`).
  - Standard 8-byte response header:
    - Byte 0: `response_code` (uint8 `B`) — 1 (Index), 2 (Ticker), 4 (Quote), 5 (OI), 8 (Full), 50 (Disconnect).
    - Bytes 1-2: `msg_length` (uint16 `H`) — Total payload / packet length.
    - Byte 3: `exchange_segment` (uint8 `B`) — Segment enum mapping (NSE_EQ, NSE_FNO, etc.).
    - Bytes 4-7: `security_id` (int32 `i`) — Numeric security ID.
  - Packet structures:
    - `IndexPacket`: Header + LTP (float32) + LTT (int32).
    - `TickerPacket`: Header + LTP (float32) + LTT (int32).
    - `QuotePacket`: Header + LTP (float32) + LTQ (uint16) + LTT (int32) + AvgPrice (float32) + Volume (uint32) + TotalBuyQty (float32) + TotalSellQty (float32) + DayOpen (float32) + DayHigh (float32) + DayLow (float32) + DayClose (float32).
    - `OIPacket`: Header + OpenInterest (uint32).
    - `FullPacket`: QuotePacket fields + 5-level Depth Ladder (5 Bids + 5 Asks with Price, Quantity, Orders).
    - `DisconnectPacket`: Server disconnect signal.
- **Robustness and State Safety**:
  - Truncated bytes (< 8B or incomplete payload) and malformed headers raise `CorruptPacketError` or return clean error indicators.
  - Parser never raises unhandled exceptions or corrupts client stream state.
- **Connection Lifecycle & Reconnect State Machine**:
  - States: `DISCONNECTED`, `CONNECTING`, `AUTHENTICATING`, `CONNECTED`, `RECONNECTING`, `FAILED`.
  - Heartbeat tracking with ping/pong timer.
  - Exponential backoff reconnect strategy with jitter.
- **Golden Packet Fixtures**:
  - Stored in `backend/tests/fixtures/golden_packets/`.
  - Zero secrets/credentials: synthetic real-shape binary packets.
  - Independent bit-for-bit decode test verifying all fields against reference models.

## Required deliverables

1. `backend/app/dhan/packets.py` — Typed packet definitions, binary header/payload parser, and packet serializer.
2. `backend/app/dhan/feed.py` — WebSocket feed client, heartbeat mechanism, and reconnect state machine.
3. Golden binary packet fixtures in `backend/tests/fixtures/golden_packets/`.
4. `backend/tests/unit/test_dhan_feed_packets.py` — Packet parser unit tests, golden packet decode, and fuzzing/corruption resilience tests.
5. `backend/tests/unit/test_dhan_feed_client.py` — Client connection state machine, heartbeat, and reconnection tests.
6. `docs/qa/acceptance/F7.1.md` — Acceptance contract.

## Acceptance scenarios

### E1 — Independent golden-packet decode
- Golden binary packets for Index, Ticker, Quote, OI, and Full packets decode bit-for-bit into exact model fields without loss of precision.

### E2 — Truncated and corrupt packet safety
- Truncated bytes (< 8 bytes, partial payload, corrupted headers, negative lengths) are safely rejected without throwing unhandled exceptions or corrupting client state.

### E3 — Reconnect state machine and heartbeat
- Connection drops trigger transitions from `CONNECTED` to `RECONNECTING` with exponential backoff and successful reconnection to `CONNECTED`.
- Heartbeat missed ping/pong triggers reconnect cleanly.

### E4 — Zero credential exposure
- No Dhan client ID, access token, or user credential is present in packets, logs, exceptions, or test fixtures.
