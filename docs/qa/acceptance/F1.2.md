# F1.2 Acceptance Contract — Dhan Daily Backfill Since Inception

## Feature

Dhan daily historical backfill since inception with resumable windows, immutable raw ingest provenance, corporate-action-adjustment investigation metadata, independent NIFTY sample reconciliation, and atomic publication to the warehouse.

## Scope decisions recorded before implementation

- **Resumable Windows & Job Tracking**:
  - `DailyBackfillManager` tracks backfill tasks with symbol, segment, date range, completed windows, and status.
  - Interrupted runs resume from the last completed window without requesting duplicate data.
- **Immutable Raw Ingest Artifacts**:
  - Raw JSON responses are persisted under `data/raw/dhan/charts_daily/<YYYY>/<MM>/<ingest_id>/payload.json`.
  - Accompanying `metadata.json` records provider, non-secret parameters, timestamps, status, payload hash, and explicit redaction list (ADR-0005).
- **Corporate Action Adjustment Investigation**:
  - Records explicit `adjustment_status` (`"unadjusted"`, `"adjusted"`, `"investigation_pending"`) in backfill metadata and manifest notes.
  - Ensures no equity backtest is marked fully trusted until corporate action adjustment status is verified.
- **Warehouse Promotion**:
  - Batches daily bars into typed `BarRecord` instances, stages Parquet partitions, and atomically publishes warehouse versions via `WarehousePublisher` (F1.1).
- **Independent Reconciliation**:
  - NIFTY daily index sample is tested against expected historical reference points.

## Required deliverables

6. `backend/tests/integration/test_daily_backfill_resumable.py` — Integration tests for resumable backfill execution, raw ingest provenance, and warehouse publication.

## Acceptance scenarios

### B1 — Raw ingest artifact creation with redacted provenance
- Executing a daily backfill writes raw payload and `metadata.json` with exact SHA-256 and zero leaked credentials.

### B2 — Resumable window execution
- Simulating a partial backfill interruption resumes from the uncompleted date window without duplicating existing bars.

### B3 — Warehouse publication of daily bars
- Staged daily bars are promoted to the active warehouse version with correct partition metadata and can be queried via `WarehouseReader`.

### B4 — Corporate action adjustment metadata
- Backfill results explicitly include `adjustment_status` tracking.

### B5 — Independent NIFTY reconciliation
- NIFTY daily OHLCV bar sample reconciles accurately against independent reference fixture.
