# F13.4 Acceptance Contract: Nightly Postgres/Parquet/Config Backups, Retention, Encryption, Integrity Checks, and Documented Restore

## Feature Definition
- **Feature ID**: F13.4
- **Name**: Nightly Postgres/Parquet/config backups, retention, encryption, integrity checks, and documented restore.
- **Dependencies**: F13.2, F13.3
- **Proof Requirement**: Restore into a clean staging box succeeds and reconciles counts/hashes.

## Invariants & Acceptance Criteria

1. **Comprehensive Backup Scope (`backend/app/backup/`)**:
   - **Postgres Database**: Authoritative transactional data (orders, trades, positions, journal entries, audit logs, strategy configs). Dumper records exact table-level row counts and data checksums in manifest.
   - **DuckDB Parquet Warehouse**: Immutable historical tick and bar partitions stored under `data/warehouse/`.
   - **System & Strategy Configuration**: Grading thresholds, trading calendars, runbooks, and manifests, with strict secret redaction.

2. **Cryptographic Integrity & Manifest Verification**:
   - Every backup archive generates an authoritative `BackupManifest` recording:
     - `backup_id`, `created_at`, and `git_commit_sha`.
     - File-level SHA-256 digests and byte sizes for all Parquet partitions and configuration files.
     - Table-level row counts and deterministic content hashes for all Postgres tables.
     - Global archive SHA-256 digest.
   - Tamper Detection: Any altered bit in the archive, Parquet files, or database dumps immediately fails integrity verification.

3. **Encryption at Rest**:
   - Backup archives support optional authenticated encryption (e.g. AES-256-GCM / PBKDF2 key derivation) to safeguard cold historical backups on remote storage/S3.

4. **Retention Policy & Pruning**:
   - Automatic pruning enforces configurable retention windows:
     - Default: 30 nightly backups, 12 monthly backups.
     - Pruning safely removes expired backups while strictly protecting the latest N snapshots.

5. **Clean-Box Restoration Engine**:
   - `restore_backup(archive_path, target_box_root)`:
     - 1. Verifies archive checksum against recorded digest.
     - 2. Extracts database dumps, Parquet warehouse partitions, and configurations into an empty clean staging environment.
     - 3. Reconciles every restored file's SHA-256 digest against the original backup manifest.
     - 4. Reconciles all database table row counts and content hashes against the original manifest.
     - 5. Produces a `RestoreVerificationReport` showing exact match with 0 discrepancies.

6. **Operational Runbook**:
   - `docs/runbooks/backup-restore-disaster-recovery.md` detailing automated nightly cron/systemd timers, manual snapshot commands, backup verification, and full clean-box disaster recovery restore procedure.

7. **Verification & Proof Suite (`backend/tests/unit/test_backup_restore.py`)**:
   - Creates a synthetic staging production state with Postgres tables, Parquet warehouse partitions, and configs.
   - Generates encrypted/signed backup bundle and manifest.
   - Restores the bundle into an entirely separate clean staging box directory.
   - Confirms that 100% of row counts, file counts, and SHA-256 hashes reconcile identically.
   - Injects tampering into an archive and confirms restore fails closed with `IntegrityCheckFailedError`.
   - Verifies retention pruner preserves active retention window and discards expired backups.
