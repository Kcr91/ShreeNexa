# F12.4 Acceptance Contract: Account Risk Layer, Kill Switch, Caps, and Broker-Path Enforcement

## Feature Definition
- **Feature ID**: F12.4
- **Name**: Account risk layer: kill switch (including broker-level `/v2/killswitch` and `DELETE /v2/positions` Exit All), capital/loss/position/order-rate/price-band caps, and broker-path enforcement.
- **Dependencies**: F3.1, F9.3, F12.1, F12.2, F12.3
- **Proof Requirement**: Exhaustive test proves no path reaches DhanBroker without risk filtering; kill switch halts within one tick and triggers broker-side fail-safe if authorized.
- **Protected Path**: `backend/app/engine/risk.py`

## Invariants & Acceptance Criteria

1. **Pre-Trade Risk Filtering & Caps (`backend/app/engine/risk.py`)**:
   - Order Value Cap: Single orders with notional value (`quantity * price`) exceeding `max_order_value` (e.g. ₹5,00,000) are rejected before reaching the broker.
   - Price Band Cap: Orders with limit prices deviating by more than `price_band_pct` (e.g. ±10%) from reference LTP are rejected to prevent fat-finger executions.
   - Position Count Cap: New order entries that would exceed `max_open_positions` are rejected.
   - Order Velocity Cap: Rate of orders per second cannot exceed `max_orders_per_second` (default 10 req/s conforming to Dhan order limits).

2. **Emergency Kill Switch**:
   - Engine Halt: Activation of the kill switch transitions the engine to `HALTED` within one tick. All subsequent order placements, modifications, or slicings are immediately rejected with `KillSwitchActiveError`.
   - Broker Fail-Safe Delegation:
     - When authorized with `exit_all_positions=True`, calls Dhan broker endpoint `DELETE /v2/positions` to liquidate open positions.
     - When authorized with `activate_broker_killswitch=True`, calls Dhan broker endpoint `POST /v2/killswitch?killSwitchStatus=ACTIVATE` to disable trading at the broker account level for the remainder of the session.
   - Idempotency: Multiple activations of the kill switch are idempotent and safe.

3. **Mandatory Broker-Path Enforcement**:
   - Every execution path directing orders to `DhanBroker` is strictly routed through `RiskFilteredBroker` / `RiskEngine.filter_order()`.
   - Direct calls that attempt to bypass the risk filter raise `RiskCheckFailedError`.

4. **Zero Real Broker Order Placement in Tests**:
   - All tests use injected offline mock transports. No real broker network traffic or order placement occurs.

## Required Deliverables
1. `backend/app/dhan/client.py` — Add broker kill switch (`get_kill_switch_status`, `manage_kill_switch`) and position liquidation (`exit_all_positions`) client methods.
2. `backend/app/engine/risk.py` — Implement `RiskLimits`, `RiskEngine`, `RiskFilteredBroker`, `RiskCheckFailedError`, and `KillSwitchActiveError` (Protected path).
3. `backend/tests/unit/test_risk_engine.py` — Exhaustive unit and safety tests verifying caps, kill switch halting within one tick, broker fail-safes, and broker-path enforcement.
